C! (C-Bang) - Complete Feature Inventory
=========================================

This file lists EVERYTHING the compiler currently has, as verified by
testing each item. Anything listed as "not implemented" was tested and
rejected by the compiler.

Last verified: 2026-10-26

2. TYPES
========

14 fixed-width primitive types. All sizes are guaranteed:

    i8    signed 8-bit        u8    unsigned 8-bit
    i16   signed 16-bit       u16   unsigned 16-bit
    i32   signed 32-bit       u32   unsigned 32-bit
    i64   signed 64-bit       u64   unsigned 64-bit
    f32   32-bit float        f64   64-bit float
    bool  true/false          str   string slice
    void  no value            uintptr  address-sized integer

Pointer types:  *T          (e.g. *i32, *Point)
Named types:    struct, union, enum, type aliases

Mapped to C as: int8_t..uint64_t, float, double, bool,
                {const uint8_t* ptr; uint64_t len;}, void, uintptr_t


3. LITERALS
===========

Integers:
    42          decimal
    0xFF        hex
    0b1010      binary
    0o17        octal

    Full unsigned range: 18446744073709551615 fits.
    Literals are never negative on their own -- `-5` is unary minus
    applied to 5, so u64's whole range is available.

Floats:
    3.14
    1.0

Strings:
    "hello"     double quotes

Chars:
    'A'         single quotes

Bools:
    true  false

Escape sequences (in strings, passed to C):
    \n  \t  \\  \"  \0  \r

Escape sequences (in char literals):
    \n  \t  \r  \0  \\  \'


4. OPERATORS
============

Arithmetic:        +  -  *  /  %
Compound assign:   +=  -=  *=  /=  %=
Comparison:        ==  !=  <  >  <=  >=
Logical:           &&  ||  !
Bitwise:           &  |  ^  ~  <<  >>
Bit compound:      &=  |=  ^=  <<=  >>=
Assignment:        =

Address-of:        &expr       (prefix position only)
Dereference:       *expr       (prefix position only)
Field access:      expr.field  (works through pointers too)
Field access:      expr->field (explicit pointer form)

Delimiters:        ( )  { }  [ ]  ,  ;  :

Precedence follows C. Postfix (call, index, field) binds tightest.


5. DECLARATIONS
===============

Variables:
    var x: i32 = 10;
    var y: i32;              // no initializer allowed

Constants (read-only, enforced by the compiler):
    const MAX: u32 = 100;
    const SIZE = sizeof(i32);   // type inferred

Volatile (emits C's volatile):
    volatile var reg: u32 = 0;

Structs:
    struct Point { i32 x; i32 y; }

Unions:
    union Data { i32 i; f32 f; }

Enums:
    enum Color { RED, GREEN, BLUE }
    enum Code { OK = 0, FAIL = 1 }     // explicit values

Type aliases:
    type usize2 = u64;

Functions:
    fn add(a: i32, b: i32) i32 { return a + b; }

Visibility:
    pub fn foo() ...     // visible outside the file
    fn foo() ...         // private, emits C static

    pub main is not required - main is never made static
    regardless, so the linker always finds it.

External C functions:
    extern fn abs(x: i32) i32;
    - declaration only, no body
    - never emitted as static
    - parameter NAMES are required (unnamed params rejected)
    - you must have the C header/symbol available at link time

Modules:
    use std.io;
    use std.os;


6. STATEMENTS
=============

if / else:
    if (cond) { ... } else { ... }
    else if chains work

while:
    while (cond) { ... }

for (3-clause only):
    for (var i: i32 = 0; i < 10; i = i + 1) { ... }

switch (C-style fallthrough - no automatic break):
    switch (x) {
        case 1: { ... }
        case 2: { ... }
    }
    NOTE: no `default:` keyword exists yet. Tested and rejected.

break / continue:
    inside loops and switch

return:
    return;         // void functions
    return value;

defer (LIFO cleanup, runs on scope exit AND early return):
    defer { cleanup(); }
    - registered in order, runs in reverse
    - runs before every return
    - return inside defer is a compile error

Blocks:
    any { ... } block introduces its own scope

Compound assignment:
    x += 1;  x -= 1;  x *= 2;  x /= 2;  x %= 3;
    x <<= 1; x >>= 1; x &= 2;  x |= 2;  x ^= 2;


7. EXPRESSIONS
==============

Function calls:        add(1, 2)
Module calls:          io.print("x"), os.exit(1), math.sqrt(2.0)
Casts:                 x as i64
sizeof:                sizeof(i32)
alignof:               alignof(f64)
Address-of:            &x
Dereference:           *p
Field access:          p.x  (auto-derefs if p is a pointer)
Indexing:              s[i]  (pointers and str)
String member:         s.len  (u64), s.ptr  (u8*)
Nested access:         o.in.v  (verified working)


8. BUILT-IN MODULES
====================

std.io:
    io.print(value)      -> writes to stdout, no newline added

    Accepts: str, i8..i64, u8..u64, f32, f64, bool, and integer literals.
    Integers print in full, including u64 max.
    Rejected with an error: struct, union, enum, pointer.

std.os:
    os.exit(code)        -> exits with that code

std.math:
    math.abs(x)          -> absolute value
    math.min(a, b)       -> smaller of the two
    math.max(a, b)       -> larger of the two
    math.sqrt(x)         -> square root
    math.pow(x, y)       -> x to the power y
    math.floor(x)        -> round toward -inf
    math.ceil(x)         -> round toward +inf
    math.round(x)        -> round to nearest

    Types:
      abs keeps the argument's type: int in, same int out; f64 in, f64 out.
            On unsigned values it is the value itself (already >= 0).
      min/max pick the helper from the arguments: both signed -> i64 helper,
            both unsigned -> u64 helper, either float -> double helper.
            An int literal takes the other side's signedness, so
            math.max(count, 0) works without a cast.
            Signed mixed with unsigned, or a float mixed with a plain int
            variable, is a type error rather than a silent conversion.
      sqrt, pow, floor, ceil, round always return f64.
            Arguments may be any number; C promotes them.

    Each argument is evaluated exactly once: math.min(bump(), 5) calls
    bump() one time. A (a<b?a:b) expression would have called it twice.

    sqrt/pow/floor/ceil/round/abs-on-float lower to libm, so the driver
    adds -lm to the cc command. Only when the program actually uses them:
    `use std.math` alone adds nothing, and neither does math.min.

Unknown modules produce an error listing what exists.

The void message reads "<what> cannot have type 'void'", where <what> is
variable / constant / field / parameter / global / alias.

Declaration order rule: a struct field, alias or global initializer may only
name a type (or another global) declared above it by value. Through a
pointer any order is allowed, because codegen emits a forward
`typedef struct X X;` for every struct and union first.

Type rules:
    - integer literals are untyped until context decides
      (so `var i: u32 = 0;` works)
    - int <-> int, int <-> float, float <-> float convert freely
      (C-style promotion; use `as` to be explicit)
    - 0 initializes any pointer (null pointer)
    - conditions must be bool or int
    - type aliases are resolved before checking


10. COMMAND LINE
================

    cbang build file.cb              compile to binary
    cbang build file.cb -o name      name the output
    cbang file.cb                    parse only, print the AST
    cbang file.cb --tokens           print the token stream
    cbang --test                     run built-in self test

Compilation chain:
    file.cb -> lexer -> parser -> sema -> file.c -> cc -> file

12. NOT IMPLEMENTED (tested, compiler rejects these)
====================================================

    switch default:          no `default` keyword exists
    fixed-size arrays        var a: [5]i32;   -> parse error
    unnamed extern params     extern fn puts(str) i32; -> parse error
    multi-file projects      one .cb file at a time
    string building          only literals, .len and .ptr
    closures / nested functions
    generics / templates
    method syntax on structs (no obj.method() - use free functions)
    foreach-style loops      only the 3-clause for
    modules beyond std.io, std.os and std.math
    header inclusion for extern  (you declare symbols, no #include emitted)


13. CODEGEN NOTES
=================

Emitted C is clean under -Wall -Wextra (zero warnings).

Emission order:
    1. headers, runtime string helpers
    2. forward `typedef struct X X;` / `typedef union X X;` for every
       aggregate -- so a struct can hold a pointer to itself (linked
       lists) or to a type defined further down the file
    3. struct/union/enum/typedef/const/globals bodies
    4. function prototypes (all forward-declared)
    5. function bodies

Other details:
    - private functions get C's `static inline`
      (bare `static` + unused = gcc's -Wunused-function against generated
       code; `inline` silences that, and C! reports the unused private
       function itself, against the user's line)
    - a non-void body that sema proved never falls off its end (it ends in
      `while (true)` or `os.exit()`) gets an unreachable
      `return (T){0};` inside its closing brace, so gcc does not warn
      -Wreturn-type about the generated file
    - `os.exit()` sets the <stdlib.h> need during the pre-scan, so the
      header is present even if the program forgot `use std.os`
    - main is never static
    - extern functions are never static
    - defer is lowered to plain C at scope exits and returns
    - `p.x` on a *Point becomes C's `p->x`
    - compound assignment is desugared (a += b -> a = a + b)
    - switch keeps C fallthrough behavior


14. KNOWN LIMITATIONS / TODO
============================

    - small memory leaks at exit (about 1 KB for a larger program: Type
      objects that live for the whole run). Harmless for a short-lived
      CLI; AddressSanitizer reports no invalid access and the full suite
      is clean under ASan + UBSan.
    - switch has no default case
    - no fixed arrays
    - no source snippet in error messages (no caret ^^^ line yet)
    - floats print with C's %g, so 3.0 prints as "3"
    - unused *local* variables still reach gcc as -Wunused-variable;
      only private functions are reported by C! itself
    - io.print / os.exit / math.* may be called without the matching
      `use` line -- `use` is not enforced as a precondition
    - std.math has abs, min, max, sqrt, pow, floor, ceil, round.
      No sin, cos, log, exp, atan2 or integer division helpers yet.
